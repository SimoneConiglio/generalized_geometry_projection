Developer Guide

This guide outlines the mathematical foundation, architectural patterns, and engineering decisions behind the ggp framework.

Mathematical Foundation

The Generalized Geometry Projection (GGP) method parametrizes a design domain using explicit geometric primitives (e.g., rectangles, ellipses) rather than a dense grid of pixel densities. This framework implements the 2D Free formulation based on the original work by Coniglio et al.

1. Primitive Mapping

Each component \(i\) is defined by a set of continuous variables \(x_i = [X_c, Y_c, L, H, \theta]\), representing its center coordinates, length, thickness, and orientation angle.

To determine the density contribution of a primitive at any spatial point \((x, y)\), the method computes the projection in four steps:

Step 1: Local Coordinates The coordinates are translated and rotated to the component’s local reference frame:

\[\Delta x = x - X_c, \quad \Delta y = y - Y_c\]
\[x_{loc} = \Delta x \cos\theta + \Delta y \sin\theta\]
\[y_{loc} = -\Delta x \sin\theta + \Delta y \cos\theta\]

Step 2: Skeleton Distance The distance \(\psi_i(x,y)\) from the point to the component’s central skeleton (a line segment of length \(L\)) is calculated:

\[d_x = \max(0, |x_{loc}| - L/2)\]
\[\psi_i(x, y) = \sqrt{d_x^2 + y_{loc}^2}\]

Step 3: Signed Distance The signed distance variable \(\zeta\) evaluates whether the point is inside or outside the component’s boundary (thickness \(H\)):

\[\zeta = \psi_i(x, y) - H/2\]

(\(\zeta < 0\) inside, \(\zeta > 0\) outside).

Step 4: Regularized Mapping To ensure strict differentiability for gradient-based optimization, the local density \(\rho_i(x,y)\) is mapped from \(\zeta\) using a smoothed area-fraction function over a narrow transition band \(r_{gp}\):

\[\begin{split}\rho_i(x, y) = \begin{cases} 1 & \text{if } \zeta < -r_{gp} \\ \delta_{min} + (1 - \delta_{min}) \frac{1}{\pi} \left( \arccos(z) - z \sqrt{1 - z^2} \right) & \text{if } -r_{gp} \le \zeta \le r_{gp} \\ \delta_{min} & \text{if } \zeta > r_{gp} \end{cases}\end{split}\]

where \(z = \zeta / r_{gp}\) is the normalized distance inside the transition band, and \(\delta_{min}\) is a tiny void density (e.g., \(10^{-6}\)) to prevent global stiffness matrix singularities.

2. Saturated Kreisselmeier-Steinhauser (KS) Aggregation

To combine multiple overlapping components into a single global density field \(\rho(x, y)\), the KS function is used as a smooth approximation of the maximum operator:

\[KS(\rho) = \frac{1}{\kappa_a} \ln \left( \frac{1}{N} \sum_{i=1}^N \exp(\kappa_a \rho_i) \right)\]

Because the KS function can exceed 1.0 (causing issues for physics solvers), we apply a smooth saturation function to strictly bound the final density \(\rho \in [0, 1]\).

3. Continuous Additive Layer Manufacturing (ALM) Mapping

The ALM formulation constructs a cohesive part made of \(N_y\) stacked horizontal layers (or trapezoidal segments). The design variable vector has the following interleaved layout (matching the GGP_ALM Matlab reference):

[Xc_0_0, L_0_0,  Xc_0_1, L_0_1,  …,  Xc_{Ny-1}_{Np-1}, L_{Ny-1}_{Np-1},
 h_0, …, h_{Np-1},
 Mc_0, …, Mc_{Np-1},
 y0, theta0]

  • \(X_{c,k,j}\), \(L_{k,j}\) — x-centre and width of column \(j\) in layer \(k\)

  • \(h_j \in [0.2,1]\) — normalised total print height per column (\(N_p\) values)

  • \(M_{c,j}\) — membership density per column, shared across all layers

  • \(y_0\), \(\theta_0\) — global printing-plane offset and rotation

Total variables: \(2 N_y N_p + 2 N_p + 2\).

The characteristic function uses the quintic MNA window and a height cutoff \(\zeta_3 = y_p - L_y h_j\) to terminate each column at its total print height. Left/right boundary tests are linearly interpolated between adjacent layer interfaces to produce smooth trapezoidal segments. Overhang and bridge-length constraints are linear in the \((X_c, L)\) variables; see Additive Manufacturing Constraints for full details.

Finite Element Solver

The physical evaluation is handled by a FEniCS-based Linear Elasticity solver. It takes the projected continuous density field \(\rho(x, y)\) and evaluates the mechanical compliance (stiffness) of the structure.

1. Material Penalization (SIMP) We use the Solid Isotropic Material with Penalization (SIMP) model to interpolate the Young’s modulus \(E\):

\[E(\rho) = E_{min} + \rho^p (E_0 - E_{min})\]

where \(p=3.0\) is the penalization power, \(E_0 = 1.0\) is the solid stiffness, and \(E_{min} = 10^{-6}\) is a tiny void stiffness to prevent a singular matrix.

2. Constitutive Relations The stress tensor \(\sigma(u)\) for a displacement field \(u\) under the assumption of linear isotropic elasticity is:

\[\sigma(u) = \lambda \text{tr}(\varepsilon(u)) I + 2\mu \varepsilon(u)\]

where the linear strain is \(\varepsilon(u) = \frac{1}{2}(\nabla u + (\nabla u)^T)\). For 2D Plane Stress formulations, the Lamé parameters are defined using Poisson’s ratio \(\nu = 0.3\):

\[\lambda = \frac{E \nu}{1 - \nu^2}, \quad \mu = \frac{E}{2(1+\nu)}\]

3. Variational Weak Form The solver finds the displacement \(u \in V\) that satisfies the weak form of the equilibrium equation:

\[\int_\Omega \sigma(u) : \varepsilon(v) d\Omega = \int_{\partial \Omega_N} t \cdot v ds \quad \forall v \in V\]

where \(t\) is the traction boundary load applied on \(\partial \Omega_N\).

4. Compliance Objective The objective function for stiffness maximization is the compliance \(C\), computed as the external work done by the applied loads:

\[C = \int_{\partial \Omega_N} t \cdot u ds\]

Architecture & Design Patterns

The ggp package is structured around four interlocking design patterns that enable extension without modifying existing code.

1. Declarative Problem Specification

Every optimisation run is fully described by a single ProblemSpec instance — a frozen dataclass tree that is the single source of truth. It is constructed from a YAML file by load_problem() and can be overridden programmatically using dataclasses.replace():

from dataclasses import replace
from ggp.problem.loader import load_problem

spec = load_problem("short_cantilever.yaml")
spec = replace(spec, volfrac=0.3,
               solver=replace(spec.solver, algorithm="SLP", max_iter=100))

Because ProblemSpec is frozen (@dataclass(frozen=True)), it is safe to share across threads and to serialize back to YAML without mutation concerns.

2. Self-Registering Geometry Readers

The ggp.geometry.io.registry module holds a global dictionary mapping geometry type strings to reader classes. Registering a new geometry source requires only a decorator — no changes to any other file:

from ggp.geometry.io.registry import register_reader
from ggp.geometry.io.base import GeometryReader, DomainRepresentation

@register_reader("my_mesh_format")
class MyMeshReader(GeometryReader):
    def read(self, spec):
        ...
        return DomainRepresentation(...)

The reader can then be referenced in any YAML file as type: my_mesh_format.

3. Self-Registering Projection Mappers

The ggp.projection.registry module follows the same decorator pattern for geometry projection. Each mapper is a pure-NumPy class (no FEniCS dependency) that implements the ProjectionMapper interface:

  • forward() — compute (rho_E, rho_V) from x_vars

  • jacobian() — compute analytic Jacobians drho_E/dx, drho_V/dx

  • num_vars_per_component() — design variables per primitive

  • default_bounds() — sensible bounds given domain extents

Adding a new mapper:

from ggp.projection.registry import register_mapper
from ggp.projection.base import ProjectionMapper

@register_mapper("Lattice_3D")
class Lattice3DMapper(ProjectionMapper):
    def forward(self, x_vars, eval_coords, power_E=1.0, power_V=1.0):
        ...
    def jacobian(self, x_vars, eval_coords, power_E=1.0, power_V=1.0):
        ...

The new mode is immediately available in the CLI via formulation.mode: Lattice_3D in a YAML config.

4. GEMSEO Discipline Wrapper

GGPGeometryDiscipline is a thin GEMSEO Discipline that:

  1. Fetches the correct mapper from the registry via get_mapper(mode, ...).

  2. Calls mapper.forward() and mapper.jacobian() in _run() and _compute_jacobian().

  3. Applies KS aggregation and smooth saturation to produce final rho_E / rho_V fields.

GGPPhysicsDiscipline wraps the FEniCS elasticity solver and computes the compliance (objective) and volume constraint value.

Both disciplines run inside a GEMSEO MDAChain driven by an MDF scenario, which handles the gradient chain-rule automatically.

FEM Solver & Pre-computed Reference Matrix

To avoid FEniCS adjoint taping overhead at every iteration, GGPPhysicsDiscipline uses a pre-computed reference stiffness matrix strategy:

  • Initialisation: A reference element stiffness matrix \(K_{ref}\) (for \(E = 1\)) is computed once via FEniCS during setup.

  • Per-iteration assembly: At each optimisation step, the global stiffness matrix is assembled by scaling \(K_{ref}\) with the SIMP-penalized modulus \(E(\rho_e)\) per element and injecting the result into a SciPy COO matrix.

  • Linear solve: The COO matrix is converted to CSR and the system \(K U = F\) is solved with scipy.sparse.linalg.spsolve (SuperLU/UMFPACK) for 2D, or with a PETSc CG + GAMG iterative solver for 3D (enabled via solver.iterative: true in the YAML or --iterative on the CLI).

Performance Monitoring

The ggp/utils/profiling.py module provides utilities to time individual pipeline stages. Profiling data is written to performance_logs/ and aggregated in performance_history.json (per Git commit).

To analyze bottlenecks in a saved .prof file, use snakeviz:

pip install snakeviz
snakeviz performance_logs/<benchmark>.prof
